      侧栏 02

      图片识题

      把截图变成题目的入口。所有内容都从这里开始。

      怎么把截图弄进来

      拖进来

      按住截图文件，拖进页面顶部的虚线框，松手即入队。

      粘贴

      截完图直接 Ctrl/⌘ + V，剪贴板里的图会自动进来。

      选文件

      点虚线框里的「选择图片」按钮，从电脑里挑一张或多张。

      手机拍照

      手机端点「拍照识题」，拍完直接进队列，不用先存到相册。

      虚线框本身不点会弹文件选择框 —— 只有「选择图片」按钮才是入口，免得看说明文字时老被弹窗打断。

      识别与校对

      1. 点「开始识别」本地 OCR（PaddleOCR）在你自己的电脑上跑，图片不会上传到任何服务器。
      2. 逐题核对每张图生成一道题：题干、选项、答案、解析。识别有偏差的地方直接改，改完再入库。
      3. 识别不准怎么办点该题的「AI 增强识别」按钮，用大模型重新解析一遍；也可以直接手改。

      「给大模型的纠正说明」是可选的：写一句「答案应为 B」「选项顺序反了」，点「AI 识别」时会一起发给模型。下次它就记住这个词了。

      解析可以写 Markdown 与公式

      解析框里支持 **加粗**、- 列表、1. 有序列表、`行内代码`、```代码块```、> 引用。写的时候，输入框下方会实时显示渲染后的样子，边写边看；内容不是 Markdown 时这块会自动收起。

      还支持 LaTeX 公式：行内公式用 $...$，独立成行的公式用 $$...$$。例如：

      $$Recall=\frac{TP}{TP+FN}$$ 会渲染成真正的分数排版，而不是一堆反斜杠。常用命令：\frac 分数、\sqrt 根号、^ 与 _ 上下标、\sum 求和、\int 积分、\text 正排文字。

      公式由内置的 KaTeX 渲染，全程离线，不需要联网。写错了会以红色标出出错的片段，不会把整段解析弄丢。

      入库与归档

      • 勾上卡片左上角的「加入题库」，再点「加入题库」或「全部加入题库」。
      • 入库后，原图会自动从「已上传图片」搬到「题目原图」目录；题库里那道题的「查看原图」照常能打开。
      • 同一张图重复上传、或题干与题库里已有的题重复，会标出提示；点提示可以直接跳去原题。
      • 想一次处理很多张：点「多选」→ 勾选 → 「批量识别」，识别结果会排成队列，一张张处理，互不打断。
      03
      侧栏 03

      整卷入库：录入一次，反复开考

      代码填空题专用，定位是纯录入与质检工具：把空白卷和答案参考录入并封存进卷库；试卷录入后会以一行出现在「我的题库」里，考试、编辑、改答案、删除都在那里完成。原来的「对照检查」退到第 02 页签做入库质检。整卷入库视图内只有两个页签：录入试卷 / 入库质检。

      1. 找到入口侧栏第 03 项「整卷入库」是纯录入工具，只有「录入试卷 / 入库质检」两个页签；试卷录入后会出现在「我的题库」里（一行一份），考试、编辑、改答案、删除都从题库那一行发起。错题本「整卷错题组」里还能「整卷重考」直接开考那一份。页面在主站内嵌切换，侧栏与顶栏常驻；点「概览」或右上「返回概览」随时回去。旧地址 /codepaper 会自动跳到 /#codepaper。
      2. 01 录入试卷填试卷名称，左边放空白代码卷、右边放答案参考（可粘贴文本，也可上传 Word / PDF / 图片 / 文本），点「解析并封卷入库」。系统识别全部空位、逐个对齐标准答案，答案随即封存，不再出现在考试页面。
      3. 02 入库质检这是入库前的答案对齐校验，不是考试：条件清单、逐空明细、回填代码与人工复核都在这里（原「对照检查」退到这一页签）。只有「每个空都绑定了正确答案」才建议开考；缺空、错位、语法角色不符都会被拦下，不会顺延补齐。
      4. 考场（开考与判分）从「我的题库」点某份卷那一行里的「开考」、或错题本「整卷错题组」的「整卷重考」进入：深色答题纸里代码原样呈现，每个空位都是输入框，顶部看已填进度与用时，下方空位导航可跳转。点「交卷并判分」后逐空揭晓你的答案 / 标准答案 / 对错，给出得分、历次成绩与整卷错题组回执；可以「整卷重考一次」或「去错题本看这一组」。整卷不拆成单题，也不进「开始练习」与「学习统计」。
      5. 在题库里修改试卷与答案录入后回到「我的题库」，每份整卷是一行：点行内「编辑」可改标题 / 类型 / 两份原文后「重新封卷」；点「改答案」只逐空订正被抽错的标准答案。两种改法都不拆整卷组，改完立即对后续开考生效。

      试卷和答案都不需要题号，空位也不需要编号；一行多个空、两份文档注释写法不同、答案用红色标注或完全没有颜色，都能处理。注释里的分值会自动忽略。标准答案只在服务端，取卷接口不下发；交卷后才随成绩单一起揭晓。

      图片试卷已支持几何横线自动检测与答案红字辅助证据，但图片来源一律算低置信度：录入后要到「入库质检」页点「确认已完成人工复核」，质检才判通过。翻拍太糊、或空位之间的括号被 OCR 漏掉时，页面会点名是哪一行并报冲突，请对照原卷手工修正；若答案含带空格的字符串字面量，也请人工复核该空。

      常见问题

      先翻这里；数据链路、接口和表结构在主章节 09「系统架构」里。

      整卷入库一个空都没识别出来？

      先确认试卷里确实有空位：文本用连续横线（____），Word 用带下划线的空白，图片用几何横线（系统会自动检出，并在结果里写明「几何横线检出 N 处」）。如果翻拍太糊、横线太短或与表格线混在一起，解析页会给出警告；此时建议把代码文字粘贴到左侧框里、把空位补成 ____ 再解析。系统不会静默把「没检测到空位」当成「试卷没有空位」。

      整卷入库的「入库质检」为什么没通过？

      切到第 02 页签「入库质检」看条件清单，哪一项是红的就是卡在哪：常见是答案数与空位数不一致、某个空没找到对应答案行，或答案与该空的语法角色不符。系统不会自动顺延补齐，避免「看起来全填了其实全错位」；把答案参考里缺的那行补上再录入一次即可。如果试卷是图片，「低置信度已复核」会一直亮红，请对照原卷逐空确认后点「确认已完成人工复核」。注意这判的是答案参考对不对，和你考试得几分是两回事。

      识别出来的题不准确怎么办？

      三种办法，从快到慢：① 直接在识别结果卡上改；② 点该题的「AI 增强识别」让大模型重读一遍；③ 填一句纠正说明（比如「答案应是 B」）再点 AI 识别，模型下次会认这个词。题目已经入库了的话，在「我的题库」里编辑，或用「用原图重新识别」。

      「已上传图片」怎么是空的？

      正常。图片入库成为题目后，原图会自动搬到「题目原图」目录，「已上传图片」只留还没生成题目的图。在「图片识题」页点「题目原图」就能看到全部原图，还能下载「题目索引.csv」按编号对号入座。

      提示「题库中已存在」怎么办？

      说明这道题的题干和题库里已有的题相同（可能是同一张图重复上传）。点那个提示徽章可以直接跳去原题核对，确认是重复就跳过这张。

      手机连不上电脑？

      去「设置」页的「手机连不上？连接自检」，那里会依次检测网络、防火墙和本机服务，并列出可直接访问的地址。同时确认手机和电脑连的是同一个 Wi-Fi。

      数据存在哪？怎么备份？

      全部在本机，不上云。「设置」页能看到数据目录、数据库大小和各类数据条数，并提供三个出口：下载数据库备份（整库）、导出 JSON、导出 CSV。换电脑时把整个数据目录拷过去即可。

      为什么键盘上能直接答题？

      练习页支持 A–D 选答案、Enter 提交、1–5 切题。要改题目本身，题库里点编辑、或练习页点「编辑本题」。

      题目里的解析能写公式和表格吗？

      公式可以：支持 LaTeX，行内用 $...$、独立成行用 $$...$$，例如 $$Recall=\frac{TP}{TP+FN}$$ 会渲染成真正的分数。Markdown 方面支持标题、加粗、斜体、行内代码、代码块、有序 / 无序列表、引用、链接、分割线；表格这类更复杂的排版暂不支持。

      错题簿 把错题变成分数 · 本地优先 · 无账号 · 无云端

      题库、练习记录与原图都保存在你自己电脑上。「设置」页随时可以下载备份或导出 CSV / JSON。

        客户端 / Client

      DESIGN INVARIANTS

      ① 无外部服务：除可选的 LLM 调用外，进程不向外发起任何网络请求；② 无账号体系：权限仅靠局域网令牌（lan_token.txt），不做用户鉴权；③ 单一进程持有数据库：SQLite 由本进程独占读写，不在多进程间共享；④ 移动端非真相源：题库与作答以电脑端为准，手机断网产生的记录联网后幂等回传。

      一道题的六次转身

      从截图到统计，每一步都有对应的模块与落盘点；去重与归档都发生在入库这一步。虚线箭头表示数据回写存储层（L4）。整卷考试有自己的录入、封卷、判分与整卷错题组链路（见 09 章）；它不接回上面的「收进题库 → 练习 → 统计」，错题本里的整卷组是并列展示的第二类条目。

        截图上传或手机拍照，落 data/uploads/；_image_digest() 用 SHA-256 算内容指纹，命中 image_hashes 即跳过重复上传。

      2. 02识别

        POST /api/ocr → ocr_engine.recognize() 跑 PaddleOCR，套用 ocr_corrections 纠错；可选 POST /api/llm/parse 补全题干/选项/解析。

      3. 03校对

        parser.parse_lines() 按段拆题，parse_segment() 提取选项与答案；前端草稿卡逐题改题干、答案与「图片中的作答」。

      4. 04入库

        POST /api/questions/bulk 先 soft_normalize() + 相似度/包含度查重再 INSERT；_archive_used_images() 把用到的原图从 uploads 移到 question_images。

      5. 05练习

        POST /api/practice/{start,answer,finish} 出题与判分，grading.grade_answer() 归一化答案；结果写 attempts 并刷新 mastery / streak。

      6. 06同步

        SSE /api/sync/stream 通知手机拉新 bundle.json；离线作答进 localStorage 队列，联网后 POST /api/sync/attempts 按 client_key 幂等回传。

      03 / RECOGNITION

      从一张截图到结构化题目

      识别不是一次 OCR 调用，而是一条可观测的流水线：图像预处理、引擎识别、阅读顺序重建、纠错、规则解析，最后才是可选的模型增强。

      1. _save_image()

        校验扩展名与大小（≤ 25MB），用 PIL 验证是否为合法图像，落盘到 data/uploads/。

      2. _image_digest()

        对流式分块计算 SHA-256 内容指纹，与 image_hashes 比对实现上传去重。

      3. ocr_engine.recognize()

        缩放/二值化预处理 → 写入 data/tmp/ 临时 PNG（不放 uploads，避免被当成用户图片）→ 引擎 .ocr() 加锁执行 → _normalize_result() → _group_lines() 重建阅读顺序，返回 lines / raw_text / elapsed / engine。整卷入库另用 recognize_detail() 拿未合并的原始 box（保留行内 x 明细）与同一张增强图，交给 codepaper/vision.py 做几何横线与红色分割；两条出口共用 _infer()，主链路行为不变。

      4. ocr_corrections

        易错词 → 正确词的词典，识别后逐行替换，纠正「0/O」「l/1」「阅渎」类笔误。

      5. parser.parse_lines()

        分段 parse_segment()：clean_text() → merge_wrapped_lines() → 定位选项起始 option_start_index() → split_inline_options() / parse_options() → answer_value() / truefalse_value() → infer_type() 推断题型 → soft_normalize() 生成去重指纹。

      6. llm_client.parse_question_image()

        可选：视觉模型把 OCR 文本补全为结构化题干/选项/答案/解析；调用失败自动降级回 OCR 结果，不阻塞入库。

      RESPONSE POST /api/ocr

      {
  "lines": [
    { "text": "1. 下列关于...的说法正确的是", "score": 0.98 },
    { "text": "A. ...   B. ...   C. ...", "score": 0.95 }
  ],
  "raw_text": "1. 下列...\n2. ...",
  "line_count": 12,
  "elapsed": 1.84,
  "engine": "PP-OCRv5",
  "image_size": [1200, 1600]
}

      FALLBACK 降级策略

      • 引擎缺失

        抛 RuntimeError，前端提示「OCR 引擎未就绪」。

      • LLM 关闭/超时

        跳过模型增强，直接用 OCR + 规则解析结果。

      • 解析为空

        返回整段 raw_text，由草稿卡手动校对。

      04 / PRACTICE

      练习会话、判分与掌握度

      一次练习是一个服务端内存会话；判分在前端与后端用同一套归一化规则；掌握度由连续答对次数驱动，作为错题筛选与复习优先级依据。

      SESSION 练习会话协议

      • start

        按 mode（random / wrong / unseen / tag / custom）筛选，返回 session_id（secrets.token_urlsafe(12)）与题目清单；会话仅存于进程内存 _sessions，服务重启即失效。

      • answer

        携带 session_id + question_id + answer；normalize_user_answer() 归一化后用 grading.grade_answer() 判分，写入 attempts 并刷新掌握度；重复提交直接返回原结果（duplicate）。

      • finish

        聚合本次会话判分结果，返回正确率、耗时与错题 id 列表。

      GRADING 归一化判分

      grade_answer(qtype, options, correct, user) 返回 (is_correct, normalized_correct)，规则：

      • single

        取首字母比较；normalize_letters() 抽取 A–Z。

      • multiple

        对答案与作答做字母集合排序后比较。

      • truefalse

        truefalse_value() 归一化「对/错/√/×/T/F」。

      • fill

        || 或 | 分隔的多候选答案，任一匹配即正确。

      MASTERY 掌握度演化（每次作答后写入）

      答对

      streak + 1；若 streak ≥ 3 则 mastery = 3，否则 mastery = max(2, 原值)；correct_count + 1。

      答错

      streak = 0；mastery = 1；wrong_count + 1。

      标记掌握

      /master 强制 mastery = 3、streak = 3。

      重置

      /reset 清零 mastery / streak / 计数，并删除该题全部 attempts。

      状态过滤口径：wrong = wrong_count>0 AND mastery<3；mastered = mastery>=3；new = 未作答；ready = 已有答案。

      07 / OFFLINE SYNC

      手机为什么断网也能做题

      不是把请求缓存下来，而是把判分逻辑与题库一起复制到本地，联网后再合并记录。整条同步链路靠「版本号 + 指纹 + 幂等键」三者保证最终一致。卷库、标准答案与考试成绩不在这份快照里：它们只存在电脑端数据库，手机端要连回同一服务才能开考或查看成绩；整卷不拆题，因此这份快照里没有来自卷库的单题。

      1

      发布快照：电脑端点「一键同步」，服务端把题库与统计打成 bundle.json，版本号 +1。

      2

      推送与落盘：/api/sync/stream 的 SSE 通知手机，手机拉快照存进 localStorage。

      3

      本地判分：离线时 /api/practice/* 在前端按同一套归一化规则判分，作答进队列。

      4

      幂等回传：恢复连接后按 client_key 提交，服务端用 sync_attempt_keys 去重，避免双写。

      SYNC PROTOCOL

      bundle.json 含 version、generated_at、questions[]（id, stem, qtype, options, answer, tags, mastery…）、stats 与 tags[]。手机先拉 /api/sync/manifest 比对版本号；仅当版本变化或收到 SSE 推送时才下载整包，避免每次轮询全量传输。

      标签列表以「名称 + 计数」计算 revision 指纹，切页 / 写操作 / 回前台 / 30 秒轮询都会校验，变了才回全量。离线作答经 POST /api/sync/attempts 按 client_key 提交，服务端用 sync_attempt_keys 去重，杜绝双写。

      09 / CODE PAPER

      整卷考试：录入、封卷、开考、整卷成组

      v1.3.0 引入的独立 Blueprint（后端旁路），v1.4.0 从「一次性对照检查」扩展成完整考试链路，v1.4.1 确立整卷不可拆分：录入 → 入库质检 → 封存卷库 → 取卷开考 → 交卷判分 → 成绩留档 → 整卷错题组。一份卷 = 一组有关联的填空题，有任意一空没答对整组进错题本，全卷全对整组移出；绝不拆成单题。标准答案只在服务端，取卷接口不下发；现有 /api/ocr、parse_lines、/api/questions/bulk 一行未改，questions 也不会被写入。v1.4.3 起整卷入库定位为纯录入与质检工具，视图内只有两个页签（录入试卷 / 入库质检）；卷库管理（显示 / 编辑 / 改答案 / 删除）已移到「我的题库」，试卷以一行呈现在题库里，考试、改卷都从那一行发起。「考场」不再作为页签，改为从「我的题库 / 错题本」的深链进入。前端仍是主站内的 .page[data-page=codepaper] 视图，两个页签共享侧栏与顶栏，codepaper.css 全部规则限定在 .cp-embed 作用域内。对应使用手册总览的 B 线（整卷主线 · 从录入到开考）。

      PIPELINE 解析与考试两条链

      A 录入 / 入库质检
  docx / pdf / image / text
    → vision.py 几何横线 + HSV 红分割
    → ingest.NormDoc → detect_blanks(global_no)
    → extract_answers（模板常量段顺序匹配）
    → fill + verify（strict，全对才 passed）
    → store.save_result → 答案封存进卷库

B 开考 / 判分
  GET  /papers/<id>/exam   → 模板 + 空位（无答案）
  POST /papers/<id>/grade  → grade_exam()
    → 逐空 squash 比对 || 等价写法
    → score / passed / 逐空批改
    → code_exam_attempts 留档
  GET  /wrong-papers            → 待攻克整卷组（不拆单题）

      核心仍是「常量段顺序匹配」：把 data = ____ 与 data = pd.read_csv(...) 去掉注释与空白后，按常量段 data= 定位，中间夹出的就是答案。verify() 判的是答案参考有没有对齐（入库质检），grade_exam() 判的是考生填得对不对（考试），两者互不替代。前端由 codepaper.js 独立驱动，所有 id / class 带 cp 前缀；概览与手册的「整卷考试」按钮用 data-cp-open 深链直接进考场。

      整卷入库入库质检判定条件
      判定条件不满足时
      空位数 == 答案数alignment_conflict，整卷退回人工，禁止自动顺延补齐
