# 错题簿 v1.4.3

一个 Windows 本地运行的「上传图片 → 自动识别 → 校对入库 → 随机练习 → 自动判分 → 错题重练」错题集软件。
v1.4.1 把 **整卷入库（codepaper）** 定为一条完整且不可拆分的考试链路：**录入卷子与答案 → 封存进卷库 → 随时整卷开考 → 交卷逐空判分 → 成绩留档 → 整卷成组进错题本**。一张卷子是一组互相关联的填空题，绝不拆成单题：有任意一个空没答对，整卷进错题本；所有空全对，整卷才移出。答案只在服务端，取卷与错题本页面都不下发。

- 不登录、不上传云端，题库和原图都留在本机
- 支持单选、多选、判断、填空，以及整卷代码填空的录入、考试、判分与整卷成组复习
- 内置离线中文 OCR，不依赖网络；整卷考试支持 Word / PDF / 图片 / 文本粘贴
- 深色侧栏 + 响应式界面；鸿蒙 7 / 手机浏览器扫码后可使用完整系统（概览、题库、练习、拍照识题）；卷库、标准答案与成绩依赖电脑端服务，不进离线同步快照；整卷不拆单题，也没有可单独同步的空位
- 自带示例题：你提供的第 46 题「数据可视化工具的主要作用」

## 二、技术实现

### 1. 整体架构

```text
电脑浏览器（HTML + CSS + 原生 JS）       手机浏览器（完整系统 / 拍照页）
        │  HTTP / JSON                      │  HTTP / JSON + 表单上传
        ▼                                   ▼
Flask 本地服务 0.0.0.0:8765（本机放行；手机须先扫码授权）
        │
        ├── SQLite（data/wrongbook.db）
        ├── 原图（data/uploads/）
        ├── OCR 引擎（PaddleOCR 3.x / PP-OCRv5 mobile）
        ├── 解析与判分模块（parser.py / grading.py）
        └── 手机待接收队列（mobile_inbox 表）
```

> 来自电脑本机地址（`127.0.0.1` 及本机各网卡 IP）的请求全部放行；同一 Wi-Fi 下的手机打开 `/p/<token>` 扫码链接后会获得一枚 HttpOnly 授权 Cookie，之后整站与所有接口都可用；未授权设备仍会收到 403 引导页。`/m/<token>` 仍是只拍照、只回传的轻量页，但提供「打开完整系统」入口。

- **后端**：Python 3.11 + Flask
- **数据库**：SQLite，零配置，单文件备份
- **前端**：原生 HTML/CSS/JavaScript，不需要 Node.js、不需要构建
- **OCR**：PaddleOCR 3.5 + paddlepaddle 3.2.2（PP-OCRv5 mobile），完全离线
- **手机拍照**：手机浏览器打开 `http://电脑局域网IP:8765/m/<token>`；拍照使用原生 `<input capture="environment">`，不需要 HTTPS，也不依赖 WebRTC / getUserMedia
- **手机完整访问**：`http://电脑局域网IP:8765/p/<token>`（设置页二维码），扫码后重定向到 `/` 并写入授权 Cookie（30 天）；令牌持久化在 `data/lan_token.txt`，**重启不变**，旧二维码与桌面图标继续有效；删除该文件并重启即可轮换令牌
- **运行方式**：默认监听 `0.0.0.0`，电脑自动打开 `127.0.0.1`；加 `--host 127.0.0.1` 可彻底关闭局域网访问

### 2. OCR 与题目解析链路

1. **图片预处理**：自动纠正 EXIF 方向；宽度不足 1800px 时按比例放大（最多 3 倍），提升小字截图识别率。
2. **文字检测/识别**：PaddleOCR 返回每个文字框的坐标、文本和置信度（`OCRResult` 以 `page.get(...)` 读取）。
3. **行还原**：按纵坐标重叠程度把同一行的文字框合并，再按从左到右排序，解决「选项字母和选项文字被识别成两个框」的问题。
4. **题目拆分**：识别 `1.`、`46 `、`第 3 题` 等题号；当前题已有选项或答案时，遇到下一题号才拆分，避免把题干中的编号误判成新题。这些题号**只用于拆分，不保存到题库**。
5. **字段解析**：
   - 选项：`A.`、`A、`、`A ` 以及四个选项被挤在同一行的情况
   - 判断题：识别为判断题后自动丢弃 A/B/C/D 选项，答案统一为「正确 / 错误」
   - 正确答案：`正确答案是 A`、`正确答案：A、C`、`参考答案 A`
   - 你的答案：`你的答案是 B`
   - 解析：`解析：...`；没有解析标签时，取答案页脚之后的有意义文本
6. **自动编号**：题目保存时按题型和当前插入顺序生成编号：
   - 单选题：`单选-1`、`单选-2`……
   - 多选题：`多选-1`、`多选-2`……
   - 判断题：`判断-1`、`判断-2`……
   - 填空题：`填空-1`、`填空-2`……
7. **质量提示**：缺少答案、缺少选项、答案选项不存在、置信度低于 78% 时给出警告；界面必须让用户确认后再入库。

### 3. 判分规则

| 题型 | 判分方式 |
| --- | --- |
| 单选 | 答案字母完全一致 |
| 多选 | 选项集合完全一致，少选/多选都算错 |
| 判断 | 统一转成「正确 / 错误」后比较；没有 A/B/C/D 选项，答题页固定显示两个选择 |
| 填空 | 忽略空白和常见中英文标点，忽略大小写；答案可用 `||` 分隔多个可接受写法，例如 `def||DEF` |

### 4. 错题与掌握度

- 答错：`wrong_count + 1`，`streak = 0`，掌握度回到「待攻克」
- 答对：`correct_count + 1`，`streak + 1`
- 连续答对 3 次：`mastery = 3`（已掌握），不再出现在默认错题重练中
- 在题库/错题本中可手动「标记已掌握」，也可在编辑弹窗里修改题目

### 5. 数据表

- `questions`：题目、选项 JSON、答案、解析、标签、原图、错误/正确次数、掌握度、指纹
- `attempts`：每次作答的答案、是否正确、模式、耗时、时间
- `imports`：每次 OCR 的原图、原始文本、文字框数据
- `settings`：初始化标记等

上列是单题主链路的 4 张常用表；`wrongbook.db` 实际共 **15 张表**：另有 `image_hashes`（上传去重）、`ocr_corrections`（纠错词典）、`sync_attempt_keys`（离线作答幂等）、`mobile_inbox`（手机回传队列），以及整卷考试旁路的 7 张表（见下一节）。

> 截图里自带的「你的答案是 B」会作为历史作答保存，但**不计入**软件内的练习正确率，避免污染学习统计。

### 6. 整卷考试（codepaper，v1.3.0 引入 / v1.4.0 扩展 / v1.4.1 整卷成组）

这是一条**独立旁路**（就后端链路而言），不改动上面 1–5 描述的单题 OCR / 解析 / 判分 / 入库链路，也不回写 `questions`。整卷以「一组填空题」的形态进入错题本，与单题列表并列展示、统计口径互不相干。

**界面位置与入口**：整卷入库不是单独打开的第二个页面，而是主站单页里的一个视图 `.page[data-page="codepaper"]`，定位是**纯录入与质检**工具（与图片识题并列，只负责把卷子和答案录进来、做好质检封存）。试卷录入后会以**一行**出现在「我的题库」顶部的「整卷考试」区块里，点行内「开考」即可进入考场；错题本「整卷错题组」里的「整卷重考」直接开考那一份卷。这些入口都带 `data-cp-open="exam"` 深链（整卷重考还额外带 `data-cp-paper="<id>"`），点进去直接开考那一份卷。整卷入库视图内只有**两个可见页签：01 录入试卷 / 02 入库质检**；「考场」不再作为页签，只通过上述深链进入。`templates/_codepaper_view.html` 由 `index.html` 以 Jinja include 引入，交互在 `static/js/codepaper.js`，样式限定在 `.cp-embed` 作用域；`app.js` 的 `VIEW_META` 统一管标题与「返回概览」动作。旧链接 `/codepaper` 仍做 302 到 `/#codepaper`。

**产品链路**

1. **录入封卷**：填试卷名称，放「空白代码卷 + 答案参考」，点「解析并封卷入库」。系统识别全部空位、按模板常量段对齐标准答案，答案随即封存，不再出现在考试页面。
2. **在题库里管理整卷**：录入的整卷以一行出现在「我的题库」的「整卷考试」区块，与单题并列但不拆题。每行可直接「开考 / 整卷重考」，也能「编辑」改标题 / 类型 / 两份原文后重新封卷，或「改答案」逐空订正标准答案——两种改法都不拆整卷组，改完立即对后续开考生效。空卷库时可在整卷入库点「载入示例卷」放一份。
3. **考场**：从「我的题库」点某行「开考」、或错题本「整卷错题组」的「整卷重考」深链进入选卷开考。深色答题纸里代码原样呈现，每个 `{{n}}` 空位是一个输入框，配已填进度、用时与空位导航。交卷后由服务端逐空判分，返回得分、你的答案 / 标准答案 / 对错，并把成绩留档；成绩单另有「整卷错题组回执」显示整组进出状态与逐空格阵，可「整卷重考一次」。
4. **整卷错题组**：按最近一次交卷判进出——有任意一空错或未作答，整卷进错题本；全卷全对，整卷移出。错题本用一张卷宗卡（一行一份卷）展示整组，格阵里每格对应一个空（赤陶=错 / 苔绿=对），并显示「共 N 题 · 错 M 题」，点「整卷重考」直接开考这份卷。整卷不拆成单题，也不进入「开始练习」与「学习统计」。
5. **入库质检**：原「对照检查」保留在此页签，负责检查答案参考有没有对齐，含条件清单、逐空明细、回填代码与图片人工复核。它判的不是考试分数。

**适用场景**：一整张空白的代码填空试卷（题目无编号），代码中多条横线是待填空位，可一行多空；另有一份填好答案的参考文档（红色标答案，也可能无颜色）；两份文件各自可能是 Word / PDF / 图片；答案片段本身不带空格；注释里的分值不关心。入库质检的验收标准仍是**每个空都绑定了正确答案**；考试则按空计分，全对才 `passed`。

**分层与统一表示**

```text
A 录入 / 入库质检
试卷 / 答案（docx · pdf · image · text）
        ↓  ingest.py（+ vision.py 图片几何横线 / HSV 红分割）
    NormDoc（pages → CodeLine → Token，统一页级坐标）
        ↓  core.py
    空位编号(global_no + 页/行/列锚点) → 答案代码块定位
        → 模板常量段顺序匹配 → 双通道(颜色 + diff)抽取
        → 回填 code_filled → verify() 全对判定 → 答案封存
        ↓  store.py
    verify_runs / blanks / answers / blank_checks / code_blocks

B 开考 / 判分 / 整卷成组
    GET  /papers/<id>/exam    模板 + 空位（无答案）
        ↓  考生逐空作答
    POST /papers/<id>/grade   core.grade_exam() 逐空比对
        ↓  score / passed / 逐空批改 → code_exam_attempts 留档
    GET  /wrong-papers        待攻克整卷组（格阵，不含答案）
```

- **格式优先级**：Word 的 `w:u` 下划线 run、PDF 文本层与 span 颜色/矢量线可精确读取，**不走 OCR**；只有图片/扫描件降级到 PaddleOCR 明细 box + `vision.py` 视觉层（几何横线形态学检测 + HSV 红色分割）。图片来源一律低置信度、强制人工复核。
- **核心算法**：把试卷行按空位切成常量段，在答案文档的对应行中按顺序定位这些常量段，夹出的文本即该空答案。一次解决「答案不带空格 / 一行多空 / 题目与空位无编号 / 两份文档注释排版不同」。常量段定位不到即报冲突，**绝不自动顺延补齐**。
- **颜色只是线索**：答案里的 `print(data.head())` 可能是「试卷已有的完整代码被标红」，因此红色片段会先与试卷非空位完整行比对，命中即判为强调标记丢弃；标题「参考答案」等噪声同样过滤。无颜色时模板 diff 通道独立工作。
- **独立校验信号**：完整性（无残留 `{{n}}`）+ 语法角色槽位（`= {{i}}` 期望表达式、`for x in {{i}}` 期望可迭代对象等）+ 人工复核。strict 模式下**不要求回填代码能编译**（答案本来不带空格）。

**接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/#codepaper` | 整卷入库视图（两个页签：录入试卷 / 入库质检；「考场」经「我的题库 / 错题本」的整卷行深链进入）；侧栏常驻、随时可返回 |
| GET | `/codepaper` | 兼容旧书签：302 重定向到 `/#codepaper` |

| GET | `/api/code-papers/demo` | 内置样例（不落库，只填输入框） |
| POST | `/api/code-papers/parse` | 解析并封卷入库：JSON（`paper_text`/`answer_text`/`title`/`language`…）或 multipart（`paper`/`answer`） |
| PUT | `/api/code-papers/papers/<id>` | 改标题 / 类型 / 两份原文后重新封卷（按新原文重新对齐封存，覆盖原卷） |
| PUT | `/api/code-papers/papers/<id>/blanks` | 逐空订正标准答案（按 `edits:[{blank_no, raw}]`，不重新解析整份卷，立即对后续开考生效） |
| POST | `/api/code-papers/seed` | 生成内置示例卷（按标题幂等，已有则复用） |

| GET | `/api/code-papers/papers/<id>/exam` | **取卷：只给模板与空位，不含答案** |
| POST | `/api/code-papers/papers/<id>/grade` | 交卷判分 → 得分、逐空批改、成绩留档 |
| GET | `/api/code-papers/papers/<id>/attempts` | 该卷的历次成绩 |
| GET | `/api/code-papers/wrong-papers` | **整卷错题组**：待攻克卷子与逐空对错格阵，不下发标准答案 |
| GET | `/api/code-papers/runs/<id>` | 某次入库质检的完整明细 |
| POST | `/api/code-papers/runs/<id>/review` | 人工复核完成并重算质检判定（硬冲突不会被复核覆盖） |

**旁路数据表（7 张）**：`code_papers`（卷子与质检状态）、`code_blocks`（代码模板与回填结果）、`blanks`（空位与锚点）、`answers`（答案序列）、`blank_checks`（对应关系与逐空校验）、`verify_runs`（每次质检快照）、`code_exam_attempts`（每次考试的成绩与逐空作答）。v1.4.0 曾给 `questions` 幂等增加 `paper_id` / `paper_seq` 两列用于拆题，v1.4.1 起整卷不拆单题，这两列成为历史遗留、不再读写。加上主链路 8 张表，全库共 **15 张**。

**数据出口边界**：这 7 张表只包含在「下载数据库备份」（整库）里；`/api/export/json` 仅导出 `questions` + `attempts`，`/api/export/csv` 仅导出 `questions`，手机同步的 `bundle.json` 也只含题库与统计——三者都不含卷子、标准答案与考试成绩，整卷成绩也不计入概览或学习统计。整卷不拆题，因此题库、导出与同步里都不会出现来自卷库的单题。

**自测**：`.venv\Scripts\python.exe -m codepaper.selftest`，覆盖 6 空完整链路、一行多空、红色噪声过滤、缺失答案拦截、常量段失配、注释差异、P1 图片视觉通道，以及考场判分（全对 / 部分对 / 未作答 / `||` 等价答案）与 v1.4.1 整卷错题组（一空错进组、全对移出、不拆单题、不下发答案），共 23 项。图片用例只跑 cv2 与组装逻辑，不启动 PaddleOCR、不写文件。

**图片通道（P1）**：`codepaper/vision.py` 用水平形态学开运算检出填空横线，并按「是否穿过文字主体、是否超长」排除表格线与页眉分隔线；用 HSV 双红区间 + 高斯/形态学抑制屏幕翻拍的摩尔纹，聚合出红色片段。OCR 明细 box 由 `ocr_engine.recognize_detail()` 提供，**保留行内 x 明细**（原有 `recognize()` 会合并同行文本、行为不变），再用字符宽度加权把横线 x 映射到文本位置，因此支持一行多空。视觉检测与 OCR 跑在同一张增强图上，空位带精确像素 bbox，前端可缩放叠加复核框。

图片来源的空位一律 `confidence=0.8 / needs_review=True`，**必须人工复核后才会判定整卷通过**；结果区的「确认已完成人工复核」按钮走 `/api/code-papers/runs/<id>/review`，只清除低置信标记，绝不会覆盖数量不符、未对齐、语法角色不匹配等硬冲突。颜色只作线索，不参与自动放行。

**当前限制**：图片质量差时 OCR 可能漏识空位之间的短标点（如 `(`），此时 warnings 会点名该行并报对齐冲突、退回人工，不会自动顺延补齐；PDF 矢量下划线的 cy 对齐、旧版 `.doc`（需另存为 `.docx`）、答案含带空格的字符串字面量（需切到 token/bbox 比较通道）仍属 P2。

```text
错题簿.lnk
```

```text
启动错题集.bat
```

## 四、使用说明

### 全局操作：侧栏折叠

- 折叠控件在侧栏**底部**：展开态是一行「收起侧栏   «」，图标态收成 44px 的双箭头按钮，与菜单用同一套圆角与高亮语言，不再有悬在主内容上的补丁。快捷键 `Ctrl/⌘ + \`。
- 桌面端（>1120px）点击在 **236px 完整菜单 ↔ 76px 图标轨道** 之间切换，主内容区宽度同步收放；折叠偏好记在浏览器本地，刷新页面后保持。
- 图标轨道是独立的一体式设计：纵向均匀渐变、右侧发丝边界、品牌下方短规则线、底部工具组分隔线、选中项贴边亮蓝条；鼠标悬停或键盘聚焦显示深色玻璃气泡（「错题本」会带待复习数量），数字徽标收成右上角小红点。
- 中等宽度窗口（681–1120px）默认也是同一条 76px 图标轨道，点底部按钮可临时展开成 236px 浮层查看文字（不挤压主内容）；点主内容、切换页面或按 `Esc` 自动收起，浮层状态不持久化。
- 手机 / 触屏设备是底部导航，不显示折叠按钮；折叠后题库页会自动按新宽度重算每页条数，分页栏仍贴底。

### 1. 上传题目

1. 左侧点击「图片识题」（或从「我的题库」点右上角「图片添加」）
2. 拖入截图，或点击「选择图片」，或直接 `Ctrl+V` 粘贴
   - 已选的图片会直接显示在「选择图片」框内，鼠标悬停可删除单张
3. 点击「开始识别」
4. 识别完成后上传区会自动收起，「识别结果」上移到屏幕上方，题目列表独立滚动

   - 勾选「加入题库」
   - 修改题干、选项、正确答案、解析、标签
   - 判断题不需要填写选项，只需确认「正确 / 错误」
   - 确认「原图答错」标记
6. 点击「全部加入题库」

保存时不会使用截图里的原题号，而是按题型和插入顺序自动编号，例如 `判断-1`、`单选-1`。识别结果中的「题库中已存在」表示题干指纹重复，默认不勾选；修改题干后可以再次加入。

保存或放弃后上传区会自动展开，可以直接继续录入下一批。

### 2. 手机拍照上传

1. 电脑和手机连接**同一个 Wi-Fi**，电脑端保持「错题簿」运行
2. 电脑进入「图片识题」，最右侧「手机拍照」卡片默认展开，直接显示二维码和地址
3. 用手机相机/微信扫一扫打开二维码
4. 在手机页面点击「打开相机拍摄」，用后置摄像头拍下题目
5. 拍完点击「发送到电脑」
6. 电脑端会自动收到照片，出现在「待识别图片」里；点击「开始识别」即可

说明：

- 手机页面使用系统相机输入，不需要安装 App，也不需要 HTTPS。
- **这个二维码只是拍照回传页，不含题库**。要看题库请用「设置 → 手机访问与同步」里的完整系统二维码，或点拍照页上的「打开完整系统 · 查看题库」。
- 访问令牌持久化在 `data/lan_token.txt`，软件重启后不变，旧二维码与桌面图标继续有效。
- 如果手机扫码打不开：
  - 打开电脑端「设置 → 手机访问与同步 → 手机连不上？连接自检」，会列出网络类别、网段、服务自检结果与候选网卡地址；有多块网卡时可直接点候选地址生成新二维码
  - 确认手机和电脑在同一网段（手机 WiFi 的 IP 前三段应与二维码地址一致），不要连访客 Wi-Fi / 流量 / VPN / 私人 DNS
  - Windows 需把当前网络标为「**专用网络**」，并允许 TCP 8765 入站；本机已添加最小范围规则 `WrongBook LAN (TCP 8765)`（仅专用网络 + 本地子网 + TCP 8765），换电脑后需重新放行。规则设为「公用网络」不生效
  - 若电脑只插网线、无线网卡是 169.254 自动地址，手机 WiFi 接在另一个路由器时二者不通，需改接同一路由器或让电脑连上该 WiFi
- 默认会监听局域网以便手机访问；如果暂时不用手机，可以在命令行运行 `python app.py --host 127.0.0.1` 关闭局域网访问。

### 2.1 在手机上使用完整系统（鸿蒙 7 / 手机浏览器）

1. 电脑保持「错题簿」运行，手机与电脑连接**同一个 Wi-Fi**
2. 电脑端进入「**设置 → 手机访问与同步**」，用**手机系统浏览器**（鸿蒙 7 可用华为浏览器）扫描卡片里的二维码，或把 `http://电脑局域网IP:8765/p/<token>` 复制到手机打开。**不要扫「图片识题」页里的拍照二维码**，那个页面只回传照片、没有题库；如果已经扫了，点页面上的「打开完整系统 · 查看题库」即可
3. 扫码后自动跳转到完整系统并写入一枚 30 天有效的 HttpOnly 授权 Cookie；之后直接打开 `http://电脑局域网IP:8765/` 无需再扫码
4. 建议在浏览器菜单里选「添加到桌面 / 添加到主屏幕」，之后可像 App 一样全屏启动（已提供 `manifest.webmanifest` 与 192/512 图标）
5. **连题库**：电脑端「设置 → 手机访问与同步 → 题库同步」点「一键同步到手机」，或手机端「设置 → 立即更新本地题库」；顶栏出现「已同步 N 题」即连上，题库 / 错题本 / 练习都能看（详见 2.2）

手机端已做的适配：

| 项目 | 说明 |

| 桌面图标 | PWA 支持长按图标直接进入「开始练习」或「错题本」（manifest shortcuts） |

- 首次授权与「一键同步」需要电脑开机、手机在同一 Wi-Fi 内；**同步完成后**手机本地已有题库，离开 Wi-Fi 或电脑关机也能查看和练习（见 2.2）。用流量无法首次访问，除非另行做公网部署 / 内网穿透。
- Windows 网络需标为「**专用网络**」并放行 TCP 8765；设置页「手机连不上？连接自检」会显示网络类别、服务自检与候选网卡地址，多网卡时可点候选地址换二维码。VPN / 访客网络 / 私人 DNS 可能让手机到不了电脑。
- 访问令牌已持久化在 `data/lan_token.txt`，**程序重启不会失效**，旧二维码与桌面图标继续可用；想让所有旧链接失效，删除该文件并重启即可。
- 微信内置浏览器可能限制相机与剪贴板，建议用系统浏览器；局域网是 HTTP，因此相机走系统文件输入，不依赖 HTTPS / WebRTC。

### 2.2 一键同步到手机（本地题库 / 离线可用）

同步是**单向、由电脑端手动触发**的：电脑上传完题目后点一次，手机保存一份快照，之后看题、做题不再依赖电脑。

> 「能拍照上传但看不到题目」= 扫的是 `/m/` 拍照回传码。改用设置页 `/p/` 完整系统码（或拍照页的「打开完整系统」入口），再点一次同步即可；当前快照题数可在设置页「题库同步」状态里看到。

1. 电脑端「设置 → 手机访问与同步 → 题库同步」点「一键同步到手机」，按钮旁会显示上次同步时间与题数
2. 服务端打包当前题库、错题统计、标签、概览与学习统计，写入 `data/sync/bundle.json`，版本号 +1
3. 同一 Wi-Fi 下已打开 App 的手机通过 SSE 立刻收到通知并自动更新；当时没开 App 也没关系，下次打开会自动补齐最新版本
4. 快照存进手机浏览器 `localStorage`，顶栏显示「已同步 N 题」；「我的题库 / 错题本 / 开始练习 / 学习统计」直接读本地数据

| 场景 | 行为 |
| --- | --- |
| 同 Wi-Fi、电脑在线 | 电脑点同步即推送；手机也可在设置里点「立即更新本地题库」主动拉最新。练习仍在本地即时完成，作答记录随后异步回传电脑 |
| 电脑关机 / 手机离开 Wi-Fi | App 页面保持打开时照常看题、做题：只读请求走本地快照，出题 / 判题 / 结算全部本地执行，顶栏切换为「离线 · 本地 N 题」 |
| 离线做题后连回 Wi-Fi | 每 15 秒轻量探测电脑，恢复后作答记录自动回传，按 `client_key` 去重避免重复计分，随后自动刷新本地快照 |
| 手机端新增 / 编辑题目 | 仍需电脑在线；写操作成功后自动刷新本地快照 |
| 拍照识题 / OCR | 需电脑在线（识别在电脑 CPU 上完成），离线时只做查看与练习 |

**为什么离线出题/判题不卡**：手机端练习接口一律走本地快照，压根不发 `/api/practice/*` 网络请求，所以不会出现「点了开始练习要等 TCP 连接超时」的情况；同步类请求也都带 1.2～2.5 秒短超时，连不上电脑就立刻切离线，并在离线时关闭 SSE 重连、每 15 秒静默探测一次。作答记录先写入本地队列，判题结果立即返回，回传放在后台，不阻塞答题。

**平台限制**：局域网是 HTTP，不属于浏览器认定的「安全上下文」，因此无法注册 Service Worker。手机**关掉页面后再断网重开**桌面图标时，浏览器仍可能要求先连一次服务器；只要 App 页面保持打开（或后台未被系统回收），离线使用完全正常。如果需要「任何时候冷启动都离线可用」，需要给本地服务加 HTTPS 证书或改做原生 App——这两步涉及证书信任与应用签名，没有擅自开启。

### 2. 练习

- **错题重练**：只抽待攻克的错题，最推荐
- **随机练习**：从全部题目中随机抽
- **新题练习**：只抽从未做过的题
- **按标签练习**：选择一个知识标签集中练

答题时支持键盘：`A`-`H` 选择，`Enter` 提交/下一题。提交后立即显示对错、正确答案、解析和连续答对次数。

### 3. 题库与错题本

- 题库支持按题干、解析、选项、OCR 原文搜索
- 可按题型、状态、标签筛选
- 搜索框与「题型 / 状态 / 标签 / 排序」四个下拉同处一行，窄屏时搜索框独占一行、下拉两列排布
- 错题按错误次数排序；答对 3 次自动变为已掌握
- 题目右侧可直接查看原图、标记掌握、编辑、删除
- **判断题答案按语义着色**：答案为「正确」显示绿色 `✓` 徽章，「错误」显示红色 `×` 徽章；题库卡片、识题草稿的答案下拉、编辑弹窗、练习选项与答题反馈中的正确答案都遵循这一规则（`你的答案` 仍按答对/答错着色）

#### 每页显示条数

页面**底部与分页按钮同一排**的「每页」下拉框可以决定每页显示多少条（左侧是条数、中间是页码、右侧是统计信息）：

| 选项 | 说明 |
| --- | --- |
| 自适应（默认） | 根据窗口可视高度自动计算能完整放下的条数，分页条常驻底部，列表内不出现滚动条 |
| 5 / 8 / 10 / 15 / 20 / 30 / 50 条 | 固定条数，窗口再小也不会改变 |
| 自定义… | 选中后出现数字输入框，可填 1–100 的任意整数，输入后稍停、回车或失焦即生效 |

- 固定 / 自定义档位下，一页放不下的题目由题目列表右侧的滚动条查看，分页条仍固定在页面最下方，整页不会滚动
- 列表上方会提示「本页 N 条 · 下方还有 M 条，滚动查看」，滚到底后提示改用分页继续
- 换页、切换条数或筛选后，列表自动回到本页顶部
- 选择会保存在浏览器本地，下次打开自动恢复
- 切换后会回到第 1 页，分页条右侧显示「共 N 道题 · x / y 页」
- 自适应模式下即使最后一页只剩一条，该条也不会影响全局每页条数
- 窗口尺寸变化时，自适应模式会重新计算

## 六、已知限制与建议

- OCR 对**小字、深色背景、公式、手写体**的识别有限；识别后一定要核对答案。数学公式建议手动修正。
- 如果截图只有题目和选项、没有「正确答案」，软件会提示缺少答案，需要手动填写后才能保存。
- 多选题目前是「完全匹配」判分，不支持少选得部分分。
- 填空题的多个可接受答案用 `||` 分隔，例如：`展示数据||可视化`。
- 当前是单机版，没有账号与云备份；局域网同步是「电脑 → 手机」单向快照，手机端新增/编辑题目、拍照识题仍需电脑在线。电脑关机后手机可继续查看和练习已同步的题库（App 页面保持打开时），但无法再次同步。
- 局域网 HTTP 不属于安全上下文，无法注册 Service Worker；手机彻底关闭页面后断网冷启动，仍可能需要先连一次服务器（详见 2.2）。
- 浏览器关闭后本地服务仍在运行，这是为了让「再次双击启动」能直接恢复页面；需要彻底关闭时用侧边栏「退出程序」或 `关闭错题集.bat`。
- 如果双击快捷方式没有反应，查看 `data/app.log`（UTF-8 文本），或在命令行里运行 `调试启动.bat` 查看报错。

## 七、隐私与局域网安全

- 手机访问需要局域网，因此服务默认监听 `0.0.0.0`；来自 `127.0.0.1` 的请求全部放行。
- 未授权的局域网设备只能看到 403 引导页，无法调用任何题库 / 统计 / 练习接口；二维码接口也只对电脑和已授权手机开放。
- 扫码 `/p/<token>` 后手机获得 30 天 HttpOnly Cookie；令牌持久化保存在本机 `data/lan_token.txt`，重启不会让已授权手机失效。要让所有旧链接与 Cookie 立即失效，删除该文件并重启，程序会生成新令牌。
- `/api/lan/diag` 连接诊断与 `/api/lan/qr.png?host=` 候选地址二维码只允许电脑端或已授权手机访问；二维码内容只能是本机已识别的网卡地址，不会指向任意外部地址。程序内启动的子进程可能因 WMI 权限读不到防火墙规则，此时诊断会如实标注「无法自动读取」而不是误报「规则不存在」。
- `/m/<token>` 拍照页保持最小权限：只能上传照片到待接收队列，不能读取题库。
- `/api/sync/publish`（发布快照）只接受来自 `127.0.0.1` 的请求，已授权手机也不能冒充电脑发布；`/api/sync/bundle` 仅对电脑与已授权手机开放。
- 一键同步会把题库快照写入本机 `data/sync/bundle.json`，并保存在手机浏览器 `localStorage`；数据只在电脑与已授权手机之间传输，不经过第三方。
- 手机离线练习记录回传时按 `client_key` 去重，避免网络重试造成重复计分。
- OCR 在本地 CPU 上完成，图片不会上传到第三方服务；「完全本地运行」的提示依然成立。
- 卸载/迁移前只需备份 `data/` 目录。
